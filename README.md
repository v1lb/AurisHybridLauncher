# Auris Hybrid Launcher — HOME-лаунчер для магнитолы B9520B

Kotlin + Jetpack Compose + Material 3 (своя тема). Без root, без изменений MCU/CAN/системных разделов, без платных библиотек.

> **Статус: код написан, на устройстве НЕ проверен.** Собрать APK в среде, где он был написан, было невозможно (нет Android SDK). Код прошёл синтаксическую проверку компилятором Kotlin 2.0.21; полная сборка — через GitHub Actions или Android Studio (см. ниже).

---

## 1. Анализ платформы и ограничений

| Тема | Вывод |
|---|---|
| «Android 16» на B9520B | На китайских магнитолах версию часто подменяют в `build.prop`. Реальный API-уровень покажет `getprop ro.build.version.sdk` (см. п. 8). Проект: `minSdk 26`, `targetSdk 35` — работает и на «настоящем» 16, и на подменённом 10–13. |
| Запуск Activity из фона (Android 10+) | `BOOT_COMPLETED`-ресивер **не может** открыть Hybrid Assistant. Решение: ресивер только ставит флаг, а запуск делает лаунчер, когда он сам на экране (это разрешено). |
| Сон магнитолы (ACC OFF) | Обычно это не перезагрузка, а сон. Лаунчер ловит `SCREEN_ON` (опция «после пробуждения»). Флаг автозапуска живёт 2 мин, чтобы не сработать неожиданно позже. |
| Дубликаты приложений | Запуск через `getLaunchIntentForPackage` + `NEW_TASK | RESET_TASK_IF_NEEDED` — существующая задача выводится вперёд, вторая копия не создаётся. Лаунчер `singleTask`. |
| Данные CAN/MCU магнитолы | Документированного API у штатного CAN-приложения нет → не используются. |
| Данные Hybrid Assistant | Документированный API/Intent **не подтверждён**. Лаунчер только запускает приложение и не читает его данные (по требованию «не предполагать API»). Как проверить — п. 8. |
| ELM327 | За любым адаптером один чип ELM327 — два приложения не могут безопасно слать ему команды одновременно. См. раздел 11. По умолчанию OBD2 в лаунчере **выключен**. |

## 3. Дизайн: три варианта и выбор

- **A. Toyota Touch 2** — меню-плитки как в заводской системе, энергомонитор отдельным экраном. Аутентично, но главный экран почти без данных.
- **B. Hybrid Premium** — экран целиком под энергопотоки, SOC и цифры. Красиво, но перегружен, а без OBD2 почти весь пуст.
- **C. Auris OEM+ (выбран)** — заводская палитра navy/графит, тонкие синие линии, белая лёгкая типографика; в центре энергомонитор (от B), по бокам 5 показателей, внизу док из 7 приложений (от A).
  Почему: всё главное на одном экране без перехода, крупные цели нажатия для вождения, а при отсутствии OBD2 экран остаётся полезным (часы, GPS-скорость, приложения).

Иконки — собственные линейные, логотипы Toyota не используются.

## 4. Архитектура

```
app/src/main/java/com/aurishybrid/launcher/
├─ LauncherApp.kt            — service locator, приём SCREEN_ON
├─ MainActivity.kt           — HOME-Activity, автозапуск с отсчётом и «Отменой»
├─ core/Prefs.kt             — настройки (SharedPreferences)
├─ apps/AppLauncher.kt       — поиск и запуск приложений (PackageManager/Intent)
├─ autostart/BootReceiver.kt — BOOT_COMPLETED / QUICKBOOT_POWERON → флаг
├─ data/VehicleRepository.kt — GPS + цикл опроса OBD2
├─ data/obd/Elm327Client.kt  — протокол ELM327 по Bluetooth SPP
└─ ui/                       — Compose: Home, EnergyMonitor, Settings, иконки, тема
```

Поиск приложений: Waze (`com.waze`), Google Maps (`com.google.android.apps.maps`), Музыка (`CATEGORY_APP_MUSIC`), Настройки (`ACTION_SETTINGS`) — по стандартным пакетам/интентам. FM-радио, Bluetooth и Hybrid Assistant ищутся по названию; если не найдено — кнопка ведёт в выбор приложения. Любой слот можно переназначить вручную.

## 5. Сборка APK

**Вариант 1 — GitHub (без установки чего-либо):**
1. Создайте приватный репозиторий, загрузите в него содержимое папки проекта.
2. Вкладка **Actions** → «Build APK» → **Run workflow** (или просто push).
3. Через ~5 мин скачайте артефакт `AurisHybridLauncher-apk` → `app-release.apk`.

**Вариант 2 — Android Studio:** File → Open → папка проекта → Build → Build APK(s).

`release` подписан debug-ключом — подходит для личной установки.

## 6. Установка на магнитолу

1. Скопируйте `app-release.apk` на флешку → откройте файловым менеджером магнитолы → Установить (разрешите установку из неизвестных источников).
   Или по ADB: `adb install -r app-release.apk`.
2. Запустите «Auris Hybrid» из меню приложений, разрешите **Местоположение** и **Устройства поблизости (Bluetooth)**.

## 7. Настройка

**Лаунчер по умолчанию:** нажмите кнопку «Домой» → в диалоге выберите «Auris Hybrid» → «Всегда». Если диалога нет: ⚙ (вверху справа) → «Открыть выбор главного экрана», или Настройки Android → Приложения → Приложения по умолчанию → Главный экран.
На некоторых прошивках выбор лаунчера находится в «Заводских настройках» магнитолы (часто пароль 8888 / 126 / 3368 — зависит от прошивки).

**OBD2:** см. раздел 11.

**Автозапуск Hybrid Assistant:** ⚙ → «Запускать после загрузки Android», при желании «после пробуждения», задержка 3–30 с. После загрузки появится отсчёт с кнопкой «Отмена». Если Hybrid Assistant не найден автоматически — «Быстрый доступ» → Hybrid → «Выбрать».
Возврат в лаунчер — кнопка «Домой».

## 8. Диагностика (пришлите результаты — по ним доработаю)

```
adb shell getprop ro.build.version.sdk
adb shell getprop ro.build.version.release
adb shell wm size ; adb shell wm density
adb shell pm list packages | grep -i -E "hybrid|radio|fm|bt|bluetooth|music|launcher"
adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN
```
Для проверки API Hybrid Assistant (подставьте пакет):
```
adb shell dumpsys package <пакет_hybrid_assistant> | grep -E -A3 "Receiver|Service|Provider|Activity|exported"
```
Если там есть экспортированные Provider/Receiver с документированным форматом — можно добавить чтение данных. Без этого лаунчер их не имитирует.

## 9. Восстановление штатного лаунчера

- Настройки Android → Приложения → Приложения по умолчанию → Главный экран → выбрать штатный.
- Или: Настройки → Приложения → Auris Hybrid → «Открывать по умолчанию» → «Сбросить», затем «Домой» и выбрать штатный.
- Или удалить: `adb uninstall com.aurishybrid.launcher` (система вернётся к штатному лаунчеру).

Лаунчер не меняет системные файлы — удаление полностью возвращает исходное состояние.

## 11. OBD2 по Wi-Fi (WIFI_OBDII), Toyota-параметры, Hybrid Assistant

### Подключение
1. Магнитола: Настройки → Wi-Fi → сеть адаптера (обычно `WIFI_OBDII`).
2. Лаунчер: ⚙ → «Читать данные OBD2» → Wi-Fi (TCP) → IP `192.168.0.10`, порт `35000` (типично для WIFI_OBDII; проверьте инструкцию адаптера) → «Сохранить».
3. Включите зажигание (READY) → «Проверить адаптер».

Сокет явно привязывается к Wi-Fi сети адаптера (у неё нет интернета, Android иначе отправит трафик в мобильную сеть).
**Ограничение железа:** обычно Wi-Fi модуль один — пока магнитола подключена к WIFI_OBDII, интернета по Wi-Fi нет (Waze/Maps — только через встроенный модем или SIM).

### Переподключение
При обрыве: повтор через 2 → 4 → 8 → 16 → 30 с; 3 таймаута подряд = обрыв; появление Wi-Fi сети — мгновенная повторная попытка. Статус виден на главном экране.

### Конфликт с Hybrid Assistant — сначала тест
«Проверить адаптер» открывает **второе одновременное подключение** и определяет:
| Результат | Значение |
|---|---|
| Подключение 2 отклонено / подключение 1 отвалилось | адаптер обслуживает одного клиента |
| Ответы приходят в оба подключения | общий канал, команды смешиваются |
| Каждый получает своё | несколько клиентов, но один ELM327 — AT-настройки и запросы конфликтуют |

Во всех случаях прямое одновременное подключение двух приложений ненадёжно. Два режима:

- **«Только когда лаунчер на экране»** (по умолчанию): лаунчер подключается, пока он виден, и отключается при уходе. Hybrid Assistant при этом не должен держать подключение в фоне.
- **«Прокси»**: лаунчер (foreground-сервис) держит **единственное** подключение к адаптеру и поднимает виртуальный ELM327 на `127.0.0.1:35000`. В Hybrid Assistant указать Wi-Fi адаптер `127.0.0.1:35000`. Команды выполняются по очереди, AT-настройки каждой стороны восстанавливаются при переключении; пока Hybrid Assistant опрашивает, лаунчер не шлёт своих запросов и берёт значения из его ответов.
  ⚠ Не проверено, позволяет ли Hybrid Assistant указать произвольный IP/порт — посмотрите в его настройках подключения. Если нельзя — только первый режим.

### Toyota-параметры (mode 21)
Надёжных опубликованных PID для Auris E150 нет; встроенный профиль (`assets/toyota_profile.json`) — **кандидаты** из списков Torque для Prius Gen2, помечены источником. Порядок:
1. ⚙ → «Сканировать ЭБУ» (зажигание READY, 2–5 мин): находит ЭБУ 7E0–7E7, поддерживаемые PID режима 21 и снимает сырые ответы в два круга.
2. «Поделиться» → пришлите отчёт + скриншоты Hybrid Assistant в тот же момент (SOC, t° батареи, ток). По изменяющимся байтам составляются формулы.
3. «Импорт профиля» — загрузить JSON. Формат записи:
```json
{"id":"hv_temp1","name":"t° HV-батареи 1","role":"HV_BATT_TEMP","header":"7E3","mode":"21","pid":"CF",
 "expr":"A-40","unit":"°C","min":-40,"max":90,"source":"сверено с HA 08.11"}
```
Роли: `HV_SOC`, `HV_BATT_TEMP`, `HV_CURRENT` (+ `"positiveMeans":"discharge"|"charge"`). Формулы как в Torque: `A`…`Z`, `AA`…, `SIGNED(A)`, `{A:3}`.
4. Значение попадает на главный экран **только** после переключателя «проверено» (сверка с Hybrid Assistant).
